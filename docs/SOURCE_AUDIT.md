## 需要后续验证的问题

以下是静态阅读发现的风险，尚未通过硬件复现。本阶段不改动原始固件。

1. **I²C ACK 超时返回值。** `pca9685_i2c_write_byte()` 的 `timeout` 为无符号数，循环条件使用 `timeout-- != 0U`，随后返回 `timeout != 0U`。持续无 ACK 时存在从 0 回绕的路径，可能把超时误报为成功；应补充有 ACK / 无 ACK / 边界 ACK 测试后修复。
2. **延时从出队时刻开始。** 调度线程对每个事件出队后统一 sleep 1400 ms，没有按事件时间戳扣减排队耗时；连续请求时可能偏离物料实际到达时间。舵机单轮另有两段 1500 ms 保持，吞吐量需结合实物评估。
3. **队列满和动作错误缺少可见反馈。** 请求入队使用 TX_NO_WAIT 且忽略返回值，动作队列满时没有统计；舵机写入也忽略 HAL 错误。初始化失败会每 500 ms 重试，但未见有上限的故障锁定或界面告警。
4. **模型缓冲布局依赖外部生成文件。** 后处理按固定 2100 个位置和两类布局读取，输入按固定尺寸写入；模型生成文件缺失，无法核对实际缓冲长度、输出布局和量化参数是否匹配。
5. **显示控件的能力边界。** 当前代码包含控制按钮绘制；不能只凭屏幕上的 Start/Stop 等文字，推断已实现完整触摸输入和启停联锁，需要补查输入事件链路。
